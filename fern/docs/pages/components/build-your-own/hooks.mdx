Every hook returns a handle with the same shape and reads through the session on `SchematicProvider`:

```ts
type ResourceHandle<T> = {
  data: T | undefined;      // undefined until the first successful load; retained across later errors
  error: Error | undefined; // the latest failure; cleared by the next success
  isPending: boolean;       // a request is in flight and nothing has arrived yet, or a refetch is running
  refetch(): void;
};
```

The three states a component renders follow from those fields. `data === undefined && isPending` is the first load. `data === undefined && error` is a failure with nothing to show. `data !== undefined` is ready, and a set `error` alongside it is a failure to report without replacing what is there.

Mounted outside any provider, every hook reports the missing source on its `error` rather than throwing, so a misconfigured page fails the same way a request would. Under a provider whose `session` is still `undefined`, the hooks stay pending instead. The hooks never fetch during server rendering: without `initialData` they report pending on the server and load on the client.

The company endpoints answer 404 with the message "Not found" for an account without company context enabled. Hooks surface that as an error rather than an empty answer, so a page cannot quietly report "nothing here" over real data. `httpStatus(error)` from `@schematichq/schematic-components/elements` reads the status off a billing error, and returns `undefined` for anything that was not an HTTP response.

## useCheckout

```ts
function useCheckout(): {
  open(selections?: CheckoutSelections & { creditId?: string; stage?: CheckoutStage }): void;
  setSelections(selections: CheckoutSelections): Promise<CheckoutDraft>;
  createSetupIntent(): Promise<{ clientSecret: string }>;
  finalize(input: { paymentMethodId?: string }): Promise<Subscription>;
  draft: CheckoutDraft | undefined;      // id, version, status
  snapshot: PriceSnapshot | undefined;   // dueToday, recurring, proration, lineItems, validation
  isPending: boolean;
  error: Error | null;
};
```

A persisted checkout. `open` shows the drop-in dialog. `setSelections` creates the checkout on first call and replaces its selections after that; every call re-prices on the server and returns the new snapshot. `finalize` claims the version and creates or changes the subscription. [Checkout API](/components/build-your-own/checkout-api) describes the resource underneath.

## useCompany

```ts
function useCompany(): ResourceHandle<Company>;
```

The company's current plan and add-ons with their prices in the canonical period, the subscription facts that drive notices (`trialEnd`, `postTrialPlan`, `cancelAt`, `cancelAtPeriodEnd`, `scheduledDowngrade`), the current period end, and the purchase rules that apply to it (self-service downgrade, contact-sales URL). Timestamps are RFC 3339.

## useCreditBalances

```ts
function useCreditBalances(): ResourceHandle<CreditBalance[]>;
```

Balances grouped by credit: identity and names, `total`, `used`, `remaining`, `resetsAt` or `expiresAt`, the auto top-up policy, and `grants[]` with a source enum (`plan`, `bundle`, `manual`), related names, quantities, and dates. Expired and fully used grants leave the list on the server.

## useCatalog

```ts
function useCatalog(options?: { catalogId?: string }): ResourceHandle<Catalog>;
```

Plans, add-ons, and credit bundles with prices per period and currency, tier shapes, and entitlement summaries. The mode follows the credential: a publishable key alone reads the public catalog; a session reads the company's view, which adds `current` to the plan they are on and `valid` (with a reason when false) to each change the purchase rules allow.

## useFeatureUsage

```ts
function useFeatureUsage(): ResourceHandle<FeatureUsage[]>;
```

One row per entitlement: feature identity and names, `valueType` and `valueNumeric`, `usage`, `effectiveLimit`, `percentUsed`, `isUnlimited`, `priceBehavior` with its per-period prices and tiers, `softLimit`, the credit reference and `creditEquivalentLimit` for credit-burndown features, the usage period and its reset, and per-user usage for per-seat features. Included Features and Feature Meter both read this.

## useUpcomingInvoice

```ts
function useUpcomingInvoice(): ResourceHandle<UpcomingInvoice | null>;
```

The next bill: amount due, due date, the canonical period, active discounts, and `customerBalanceApplied` and `customerBalanceRemaining` computed on the server. `null` is a loaded answer that means nothing to bill; only `undefined` means the resource has not loaded.

## usePaymentMethods

```ts
function usePaymentMethods(): ResourceHandle<PaymentMethod[]> & {
  add(): Promise<void>;                 // opens a Stripe SetupIntent and saves the result
  remove(id: string): Promise<void>;
  setDefault(id: string): Promise<void>;
};
```

Cards and wallets on file with `brand`, `last4`, `expMonth`, `expYear`, `type`, and `isDefault`. The three actions apply the same rules the drop-in enforces: the last method stays while a subscription is active, and the default is always set.

## useInvoices

```ts
function useInvoices(query?: InvoiceQuery): ResourceHandle<InvoicePage> & { loadMore(): Promise<void> };

type InvoiceQuery = { includePending?: boolean };
type InvoicePage = { invoices: Invoice[]; count: number; hasMore: boolean };
```

The invoice history, paged. `count` is how many invoices the query matches on the server, so a list showing four rows can say how many the company has. `hasMore` is that count set against the rows loaded, and an empty page ends the list regardless. `loadMore` appends the next page, settles when it lands, and never rejects; read `error` for the failure, and the rows already fetched stay put. `isPending` is true while the page is on the wire, so a button can disable itself without awaiting anything, and clicking twice makes one request. `refetch` re-requests every page loaded so far, not only the first.

`{ includePending: true }` includes unpaid invoices that are not yet due. Each distinct query is its own list with its own paging, so `useInvoices({ includePending: true })` and `useInvoices()` never share rows. The hook keys by value, so an inline object literal is fine.

An empty history is a successful response with `count: 0`. A 404 surfaces on `error`, so a page cannot report "no invoices" over a real failure.

Each `Invoice`:

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | `string` | The invoice's identifier. |
| `amountDue` | `number` | Signed, in the currency's minor units. A negative amount is a credit note. |
| `currency` | `string` | ISO 4217 code as the billing provider reports it. |
| `createdAt` | `Date` | When the invoice was created. |
| `dueDate` | `Date \| null`, optional | When it is due, if the billing provider set one. |
| `status` | `InvoiceStatus \| null`, optional | `draft`, `open`, `paid`, `uncollectible`, or `void`. |
| `url` | `string \| null`, optional | The hosted invoice page, if there is one. |

The optional fields arrive as `null` or are absent, so read them with `??` rather than a strict `null` check.

```tsx
import { useInvoices } from "@schematichq/schematic-react";

function InvoiceHistory() {
  const { data, error, isPending, loadMore, refetch } = useInvoices();

  if (data === undefined) {
    return error ? <button onClick={refetch}>Retry</button> : <p>Loading…</p>;
  }
  if (data.invoices.length === 0) {
    return <p>No invoices yet</p>;
  }
  return (
    <>
      <ul>
        {data.invoices.map((invoice) => (
          <li key={invoice.id}>
            <a href={invoice.url ?? undefined}>
              {(invoice.dueDate ?? invoice.createdAt).toLocaleDateString()}
            </a>{" "}
            {invoice.amountDue / 100} {invoice.currency.toUpperCase()}
          </li>
        ))}
      </ul>
      {data.hasMore && (
        <button disabled={isPending} onClick={loadMore}>
          Load more
        </button>
      )}
      {error && <p role="alert">{error.message}</p>}
    </>
  );
}
```

## useUnsubscribe

```ts
function useUnsubscribe(): { cancel(): Promise<void>; isPending: boolean; error: Error | null };
```

Schedules the cancellation for the end of the period, with downgrade prevention applied on the server. `useCompany` reflects the scheduled cancellation on the next read.

## useInvalidateBillingData

```ts
function useInvalidateBillingData(): () => void;
```

Returns a function that reloads every loaded billing resource while keeping its current data on screen. Call it after an action that changes what the company is billed for, such as a plan change through checkout.

```tsx
import { useInvalidateBillingData } from "@schematichq/schematic-react";

function CheckoutButton() {
  const invalidate = useInvalidateBillingData();
  return <button onClick={async () => { await openCheckout(); invalidate(); }}>Upgrade</button>;
}
```

## Testing and fixtures

`BillingDataProvider` serves fixed data to the hooks with no network and no session, so a component can be rendered in a test or a story with the rows you choose.

```tsx
import { BillingDataProvider } from "@schematichq/schematic-react";

<BillingDataProvider data={{ invoices: { invoices: [], count: 0, hasMore: false } }}>
  <InvoiceHistory />
</BillingDataProvider>;
```

A missing key reports as pending. `status` overrides a resource's `isPending` or `error`, so the loading and failure states render on demand, and `onRefetch` and `onLoadMoreInvoices` receive the calls a component makes. The provider also accepts `locale`, `strings`, `translate`, and `onMissingString`, so a fixture can exercise copy overrides too.

## Flags and entitlement checks

The hooks above read billing state. Feature flags and entitlement checks keep their own hooks on the same provider: `useSchematicFlag`, `useSchematicEntitlement`, `useSchematicPlan`, `useSchematicCreditBalance`, and `useSchematicEvents`. See the [React SDK](/developer_resources/sdks/react).
