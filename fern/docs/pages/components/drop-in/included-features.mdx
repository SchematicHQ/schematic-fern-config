The features a company has access to on its plan, with the value of each entitlement: on or off, a limit with usage against it, unlimited, or a value read from a trait.

![Included features](../../../assets/images/components/components-included-features.png)

## Usage

```tsx
import { IncludedFeatures } from "@schematichq/schematic-components/elements";

<IncludedFeatures limit={6} visibleFeatures={["seats", "projects", "api-calls"]} />
```

## Props

| Prop | Default | Effect |
| --- | --- | --- |
| `limit` | `6` | Rows shown before "See all". |
| `visibleFeatures` | all | Feature keys to show, in order. |
| `showIcons` | `true` | Feature icons. |
| `showUsage` | `true` | Usage beside limited features. |
| `showHeader` | `true` | The heading. |
| `headingLevel` | `2` | The heading's level. |
| `className`, `locale` | | Root class; BCP 47 tag for formatting. |
| `strings` | | Copy for this card by key. |

## How each row reads

The value column follows the entitlement: a check for boolean features, `3 of 4 seats` for a numeric limit with usage, `Unlimited` for no limit, and the trait's value for trait-based limits. Metered features with a price behavior show their unit price too; the fuller meter lives in [Feature Meter](/components/drop-in/feature-meter).

## Localizing it

Keys: `includedFeaturesHeader`, `includedFeaturesUnlimited`, `includedFeaturesUsage`, `includedFeaturesSeeAll`, `includedFeaturesSeeLess`, `retry`.

## Build it yourself

[`useFeatureUsage`](/components/build-your-own/hooks#usefeatureusage) returns every entitlement row, and `deriveEntitlementRow` resolves the value display into structured parts.
