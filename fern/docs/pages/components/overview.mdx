Schematic gives you two ways to put billing UI in your app. Both read one data layer, so you can mix them: a custom portal with a drop-in checkout is a normal setup.

## Which path?

| | Drop-in components | Build your own UI |
| --- | --- | --- |
| You want | Billing UI working today, in Schematic's layout, with your colors and fonts. | Your own layout in your own design system, or an agent writing it for you. |
| You write | A provider, a session, and one tag per card. | A hook call, a derivation, and the JSX. Reference code gets you most of the way. |
| Styling | `--schematic-*` tokens, `color-scheme`, or your own CSS on stable class names. | Anything. The derivations return structured parts, not sentences. |
| Checkout | `<Checkout/>`, opened through `useCheckoutLauncher()` from the handlers on Plan Manager, Credit Usage, Metered Features, and Unsubscribe Button. | `useCheckout` on the checkout API. Take payment with Stripe Elements if you like. |
| Frameworks | React. | React hooks from `@schematichq/schematic-react`. The billing client in `@schematichq/schematic-js` is plain TypeScript for any framework. |

## One setup for both

Install the React SDK and the components package. `@stripe/stripe-js` and `@stripe/react-stripe-js` are peers of the components, used by the add-card form in Payment Methods.

```sh
npm install @schematichq/schematic-react @schematichq/schematic-components @stripe/stripe-js @stripe/react-stripe-js
```

Every component and every hook reads from one provider. Your server mints a short-lived access token for the signed-in company with your secret key, so the key never reaches the browser.

```tsx
import { SchematicProvider } from "@schematichq/schematic-react";

<SchematicProvider
  publishableKey="pk_…"
  // Whose billing is being read: signed in, null for signed out, undefined while auth resolves.
  session={{ company: company.id, user: user.id, token: fetchAccessToken }}
>
  {children}
</SchematicProvider>
```

The [Quickstart](/components/quickstart) walks through the token exchange and the first component, and [Add Schematic billing to your app](/components/skill) is the same setup written for an agent.

## What's in the box

Each component imports from `@schematichq/schematic-components/elements` and renders on its own, so a page shows only the cards you place on it.

| Component | Hooks | Shows |
| --- | --- | --- |
| `<Checkout/>` | `useCheckout` | The persisted checkout |
| [`<PlanManager/>`](/components/drop-in/plan-manager) | `useCompany`, `useFeatureUsage`, `useCreditBalances` | Plan, price, add-ons, usage-based charges, plan credits, and notices like a trial ending or a scheduled downgrade |
| [`<PricingTable/>`](/components/drop-in/pricing-table) | `useCatalog`, `useCompany` | Plans and add-ons, public or company |
| [`<IncludedFeatures/>`](/components/drop-in/included-features) | `useFeatureUsage` | Every entitlement on the plan, with usage against its limit |
| [`<MeteredFeatures/>`](/components/drop-in/metered-features) | `useFeatureUsage`, `useFeatureUserUsage` | A meter per metered feature, its price and tiers, and usage by user |
| [`<CreditUsage/>`](/components/drop-in/credit-usage) | `useCreditBalances`, `useCreditUserUsage` | Balance per credit, the grants behind it, auto top-up, and usage by user |
| [`<UpcomingBill/>`](/components/drop-in/upcoming-bill) | `useUpcomingInvoice` | The next bill's amount and date, account balance, and discounts |
| [`<PaymentMethods/>`](/components/drop-in/payment-methods) | `usePaymentMethods`, `useSetupIntent` | The default method on file and an expiry warning, with an Edit dialog to add, switch, or remove methods |
| [`<Invoices/>`](/components/drop-in/invoices) | `useInvoices` | Invoice history, paged, with a link to each hosted invoice |
| [`<UnsubscribeButton/>`](/components/drop-in/unsubscribe-button) | `useCompany`, `useFeatureUsage`, `useUnsubscribe` | A cancel button that confirms, then cancels at the end of the period |
